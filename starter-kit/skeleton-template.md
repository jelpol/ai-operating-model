Every AI-managed domain of work (a job search, a business function, an
advisory practice, a compliance program) gets built from this frame. Fill
in each part for your domain. Deviations are allowed and encouraged where
your context genuinely differs, but they must be NAMED with a reason, never
silently skipped. The word "partially" is never allowed to pass silently.

## 3. Rubric

How the work gets graded before it ships. The criteria for a given piece
of work are agreed before the build starts, never discovered at grading
time, so the bar is set in advance rather than written after seeing the
result. The grade and the found weaknesses are presented WITH the work,
never silently absorbed into it, and shipped work gets retrospective
critique on a cadence. A review that produces no findings is incomplete,
not praise.

## 4. Error controls

Six minimums. Every number that drives a decision carries its value,
date, and source, marked actual or estimate. Nothing outbound skips a
final pre-flight check. Every session starts by reconciling against the
last recorded state. A shipped change set contains only this work's own
changes, verified against its claim before release. Delivery reconciles
against the itemized original ask, so nothing asked for is silently
dropped and nothing added is silently forgotten. And records under
correction stay auditable: identifiers are appended, never renumbered;
resolved findings are marked resolved in place, never deleted; and a
success claim is proven by reopening the artifact and checking observed
output, never asserted from the edit.

## 5. Learning loop

When a correction or a finished piece teaches you something, it gets
written into the right file so the next piece of work is better. Every
lesson has a named destination, and so does every artifact: before
writing anything new, confirm where it lands. Some destinations live
outside the workspace (a cross-domain inbox, a shared register), so
nothing learned anywhere is forgotten everywhere. Two additions earned
the hard way. External research never lands as a standalone summary:
anchor it to the frameworks that govern your domain, state what those
frameworks fail to capture, and link it to what you already know, because
isolated facts do not become proficiency. And lessons nobody names in the
moment accumulate silently inside long-running work, so pair the
per-lesson routing above with a sweep at closure: nothing closes until
its working files are swept for unharvested lessons and each one is
ruled into doctrine or ruled out.

## 7. Verification gate

Anything vendor, version, price, or time dependent gets verified against a
live source before it is stated, never from the model's memory. Claims
carry a confidence label: established fact, consensus practice, or judgment
call. High-stakes work gets a separate adversarial pass built to refute it.
The gate covers approaches as well as facts: before inventing a novel
mechanism, search how established practice already solves it, and credit
what you borrow. The same gates apply to changes to this system itself.
The gate also faces inward: any artifact handed to the system is
inventoried structurally and read in full before conclusions are drawn
from it; a truncated or keyword-scoped read is a stop condition, never
reported as analysis; and when someone's data contradicts what they said,
the data wins and the discrepancy becomes a finding.

## 8. Workboard

If a domain runs more than one open thread, it carries a standing board
file the session reads first: what is active now (ordered), what waits on
you, what waits on others, what is blocked and on what, what is parked,
what is done. Two hard rules make it real. The board updates in the same
commit as any work that changes it, because work not on the board means
the board was wrong. And every row that waits on a human states WHEN to
act and WHAT HAPPENS AFTER, because a decision item without its
sequencing is a pile, not a plan.
